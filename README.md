# NEXORA — نسخة تأسيسية قابلة للربط

## ما الذي يعمل؟
- واجهة عربية متجاوبة باسم NEXORA.
- عرض ثلاثة ألوان الساعة الموجودة في المستودع.
- سلة محلية للمعاينة.
- تسجيل/دخول Supabase بعد ضبط `config.js`.
- إنشاء طلب عبر RPC يحسب السعر من قاعدة البيانات ويخصم المخزون.
- عرض طلبات العميل وطلب إيداع/سحب للمراجعة.
- لوحة إدارة أولية للحساب الذي تمنحه role=admin.

## ما الذي لا يزال غير مفعّل؟
- لا توجد بوابة دفع أو تحويل بنكي آلي.
- طلب الإيداع/السحب طلب مراجعة فقط؛ لا يمثل رصيدًا حقيقيًا.
- لا توجد شركة شحن أو تتبع شحنات.
- لا توجد إدارة كاملة للمخزون/إنشاء منتجات من الواجهة بعد.
- يلزم اختبار المشروع في بيئة Supabase قبل استقبال العملاء.

## خطوات الإعداد
1. في Supabase > SQL Editor نفّذ محتوى `supabase/schema.sql`.
2. افتح `config.js` وضع:
   - `supabaseUrl`: رابط المشروع الأساسي بدون `/rest/v1/`.
   - `supabaseAnonKey`: مفتاح `sb_publishable_...` فقط.
   لا تضع `sb_secret` أو `service_role` في ملفات الواجهة.
3. ارفع ملفات المشروع إلى GitHub Pages أو استضافة HTTPS.
4. أنشئ حسابًا من واجهة الموقع ثم فعّل صلاحية المالك من SQL Editor:
   `update public.profiles set role='admin' where id=(select id from auth.users where email='YOUR_EMAIL');`
   استبدل YOUR_EMAIL ببريد حسابك. لا تمنح أي عميل آخر الصلاحية.
5. من Supabase Authentication > URL Configuration أضف رابط موقعك إلى Site URL وRedirect URLs.

## تنبيه أمني
- المفتاح العام مصمم للواجهة، لكن الأمان يعتمد على RLS وسياسات قاعدة البيانات.
- لا تضع المفاتيح السرية في GitHub.
- لا تعتمد على أرصدة شكلية أو تغييرات يدوية غير مسجلة. أي اعتماد مالي يجب أن يسبقه تحقق فعلي من التحويل.
- نفّذ SQL على مشروع جديد أو راجع الجداول الموجودة قبل التنفيذ. بعض أوامر السياسات قابلة لإعادة التشغيل، لكن إدخال المنتجات قد يكررها إذا اختلفت أسماؤها.
