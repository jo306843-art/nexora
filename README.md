# NEXORA

متجر NEXORA بواجهة عربية RTL مطابقة لملف التصميم المرجعي، مع تسجيل حسابات ومحفظة ولوحة مالك.

## ما تم ربطه في الواجهة
- تسجيل الدخول وإنشاء حساب عبر Supabase Auth.
- عرض رصيد العميل وطلبات الإيداع والسحب وسجل الحركات.
- لوحة مالك لا تظهر إلا للحساب الذي بريده **jo306843@gmail.com**.
- عرض حسابات العملاء وأرصدتهم.
- إضافة أو خصم رصيد مع تسجيل السبب والوقت ومعرّف المشغّل في سجل مالي.
- مراجعة طلبات الإيداع والسحب. لا يعتمد الإيداع إلا بعد التحقق الفعلي من التحويل.
- تغيير رقم التحويل واسم حساب Telegram من لوحة المالك، مع ظهورهما للعملاء.
- دعم Telegram الافتراضي: [@Vvcghy](https://t.me/Vvcghy).

## تفعيل قاعدة البيانات

نفّذ الملف الموحد `supabase/complete_setup.sql` مرة واحدة من Supabase SQL Editor بعد التأكد من اختيار مشروع NEXORA الصحيح. يجمع الملف إعداد الحسابات والمحافظ ومكافأة الحضور والمفضلة والطلبات والدفع من المحفظة وفودافون كاش، ويراعي أن مفاتيح المنتجات والطلبات الحالية من نوع `bigint`.

الملف لا يزرع منتجات تجريبية ولا يحذف صفوف المنتجات أو الطلبات أو المحافظ أو الأرصدة الحالية، ويحافظ على إعداد مبلغ المكافأة الذي حدده المالك عند إعادة تشغيله. لا تشغّل `supabase/brands.sql` إذا كنت لا تريد إضافة منتجات تجريبية، ولا تشغّل `supabase/vodafone_checkout.sql` القديم منفصلًا.

لا أستطيع تنفيذ SQL داخل حساب Supabase أو تأكيد نشر Cloudflare من GitHub؛ بعد تشغيل الملف بنجاح، انتظر اكتمال نشر Cloudflare Pages ثم اختبر الموقع.

## الأمان
- صلاحية المالك تتحقق على الخادم من البريد المحدد، وليس من قيمة يغيرها المستخدم في المتصفح.
- سياسات RLS تمنع العميل من تعديل الرصيد أو السجل المالي مباشرة.
- تعديلات الرصيد ومراجعة الطلبات تمر عبر دوال خادمية محمية وتُسجل في `wallet_ledger`.
- يجب التحقق يدويًا من وصول تحويل Vodafone Cash قبل اعتماد الإيداع.
- لا تضع `service_role` أو أي مفتاح سري في ملفات الواجهة. `config.js` يحتوي بيانات الاتصال العامة فقط.

## ملاحظات
- لا توجد بوابة دفع آلية أو تكامل تحقق آلي مع Vodafone Cash؛ الإيداعات والسحوبات تتم بمراجعة المالك.
- تفعيل خدمات Supabase يتطلب تشغيل ملف SQL أعلاه أولًا.
